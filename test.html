[PLATE-09 ARCHIVAL SPEC]

Case Study: AI Educational Platform (Deep-Dive)

SYSTEM SPECIFICATION · REV 2.4
01 — Context

Higher-ed curriculum coordinators manage dense syllabi across hundreds of dynamic modular disciplines. Manual quality reviews created bottlenecks of up to 4 weeks per semester update cycle.

02 — Problem

Off-the-shelf generative models suffer from catastrophic hallucination when referencing institutional course prerequisites, historical lecture notes, and regional accreditation mandates.

03 — Approach

Engineered an isolated RAG architecture running inside the existing relational boundary using PostgreSQL and pgvector, coupling semantic embeddings with BM25 keyword matching for high-precision recall.

04 — Architecture

Asynchronous ingestion pipeline splitting PDF/Markdown resources into recursive semantic chunks with sliding overlaps (512 tokens with 64-token overlap), stored with relational foreign keys.

05 — Technical Decisions

Selected pgvector over standalone vector DBs (Pinecone/Milvus) to preserve transactional ACID guarantees and avoid synchronization drifts between user permissions and chunk records.

06 — Challenges

Balancing context window saturation with LLM inference latency. Solved by implementing dynamic re-ranking via reciprocal rank fusion (RRF), discarding candidate passages below 0.78 similarity.

07 — What I Learned

Chunking heuristics outweigh model parameter size. A 7B parameter model fed meticulously chunked and ranked context consistently outperformed raw 70B zero-shot completions.

08 — Results
-85%

Reduction in content review cycles. Factual verification score reached 96.4% in blinded trials against human domain experts.
